# ExpenseLens

How can a small business categorize expenses faster, flag uncertain ones for review, and see monthly cash flow?

## Why it matters
A small-business owner or bookkeeper spends hours sorting bank-style transactions into categories. This app suggests a category for each expense, shows how confident it is, and sends the shaky guesses to a human, so review time goes to the rows that need it. A monthly dashboard shows inflows, outflows, and net cash.

## How it works
1. **Load and validate.** Upload a CSV with `date`, `description`, `amount` (positive = inflow, negative = outflow). Bad dates or non-numeric amounts produce a plain-English error instead of a crash.
2. **Dashboard.** Monthly inflows, outflows, and net cash, plus spending by category.
3. **Classify.** Choose a classifier: keyword rules, or TF-IDF + logistic regression. Both return a category and a 0-1 confidence.
4. **Flag for review.** Rows below a confidence threshold you set (slider) are flagged.
5. **Correct and export.** Edit categories in the table (double-click the cell). The CSV export keeps the original guess next to your correction and marks corrected rows.

Categories: equipment, software, marketing, travel, office supplies.

## Data
**All data is synthetic**, made up for a hypothetical photography business. No real transactions.
- `data/labeled_transactions.csv`: 234 synthetic labeled transactions (209 labeled expenses), generated by `src/make_dataset.py`.
- `data/challenge_set.csv`: 40 unfamiliar merchants, used to test how classifiers handle new names.
- `data/demo_transactions.csv`: small file for trying the app.

## Results
All numbers are from this repo's own scripts (`python -m src.evaluate_baseline`, `python -m src.compare_models`). The samples are small and synthetic, so treat them as directional.

| Test | Keyword baseline | TF-IDF + logistic regression |
|---|---|---|
| Labeled set (209 expenses) | 93.3% | n/a (the model trains on part of this set) |
| Held-out test set (48 rows) | 91.7% | 85.4% |
| Challenge set (40 unfamiliar merchants) | 5.0% | 55.0% |

- The simple baseline beat the model on familiar data. The model did far better on unfamiliar merchants.
- All 14 baseline misses on the labeled set were vague merchants (AMZN, Walmart, PayPal, SQ) that the rules marked "unknown" rather than guessing wrong.
- The model struggled most with software brand names.
- Review flagging on the demo file: at a 0.45 threshold, 5 of 10 expenses were flagged. The model got 3 wrong (Skylum, Slack, Rode); all 3 were fixed in the table and showed up as corrected in the export.
- 44 automated tests pass, including 10 edge-case tests (empty tables, zero amounts, all-inflow files, reverted edits, extreme thresholds, unknown categories, emoji and very long descriptions). The edge-case tests found no bugs.

## Limitations
- Synthetic, small data. These accuracy numbers do not predict performance on a real business's transactions.
- I wrote the keyword rules while knowing the data, so the 93.3% baseline score is optimistic.
- I tuned the 0.45 review threshold on the test set, so the review-flag results are optimistic too.
- Five fixed categories only; no way to add categories in the app.
- Out of scope on purpose: bank connections, receipt OCR, user logins, real client data.
- For real use it would need real labeled history per business, a proper validation process, and an audit trail for corrections.

## Run it
Requires Python 3.11+ (deployed on 3.14).

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    Mac/Linux: source .venv/bin/activate
pip install -r requirements.txt
python -m pytest
python -m streamlit run app.py
```

Reproduce the results:

```bash
python -m src.evaluate_baseline
python -m src.compare_models
```
